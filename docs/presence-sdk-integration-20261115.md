# Presence/Ping SDK integration, 2026-11-15

Recommended SDK revision for product consumers: **`7d17a9d36e85a8b30b5b707e28d4e7ba1b8deaf9`** (`aether-client-cpp` `main`, verified after fetch on 2026-11-15). This revision contains the context-tagged Ping, corrected peer presence aggregation, bounded local classification tolerance, and recovery probes during soft Ping quarantine. Pin this exact commit in each consuming build and rebuild its SDK. A previously inspected AppTraverse checkout at `5bbcabd2ce3a0cfcdeba336f0f5ff304849e0955` pins `cc8155d24a69c0c25b8515d4b9aebfe31c7b2180`; it is an ancestor and does **not** contain these Presence/Ping fixes. The audit's `0c2b8936` pin observation is therefore stale for that checkout. The product pin is owned by the product integration work and was not edited here.

Server requirement: the connected server must implement authorized `GetClientTiming` method 35 with pushed `SendClientTiming` method 41, plus authorized `SetSessionId` method 51 and client methods `OnSessionId` 72 and `OnResponseFor` 73. IDs for 51/72/73 use ADSL `intpack`, not fixed-width `uint64`. The server must tag the `PingAck` (method 24) response with `OnResponseFor` for the matching session ID. Confirmed against `aethernetio/aether` `main` at `4ebe268e7c1390859041eefa767822276f22c426` (ADSL and `AuthorizedApiImpl`). This is a server deployment requirement for adopting the SDK; no server source was changed in this scope.

The SDK sends `SetSessionId` and `Ping` together in one authorized packet. It gives each Ping a new context ID, ignores an unmarked or mismatched Ack, and retries a timed-out Ping on the existing transport during soft quarantine. A valid Ack releases that quarantine. There is no product-side Ping ID call to add. Consumers should use `Client::IsLocallyOnline` and `Client::QueryPeerPresence` for local and peer presence. Peer `Unknown` is meaningful: it is not equivalent to Offline. For the measured one-second configuration, set `AE_PING_INTERVAL_MS=1000`, configure `RxTimingConf::Every(1s).WithWindow(1s)` for selected servers, and use `AE_OFFLINE_DETECTION_TIMEOUT_MS=1000` (the SDK default). The native AppTraverse configuration inspected here already sets `AE_PING_INTERVAL_MS=1000`, disables UDP, and uses the default offline timeout; its product code must still configure the receive timings it intends. `AE_BENCH_TCP_PROXY` is only for explicit process-scoped fault tests.
