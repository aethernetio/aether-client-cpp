Cause and change
----------------
Previously a timed-out Ping retained the only Ack listener and blocked the next
Ping until a late Ack or ten-second soft quarantine expiry. A lost UDP datagram
cannot deliver that late Ack. The previous three-second cuts consequently had
local recovery delays of 7.127 and 7.750 seconds.

Now soft-quarantined servers receive probes on the same connection. Each probe
retires the old listener outside its callback, then uses a fresh context ID.
Only a matching Ack confirms the new receive window and releases quarantine.
Old responses cannot complete the replacement. Probe delay follows the configured
Ping interval clamped to 50 ms..1 s, after timeout. Success resumes ordinary
periodic Ping. Hard transport quarantine stops probes; the existing ten-second
expiry still reconnects if none succeeds. Request failover remains active.
Probes do not overwrite service deadlines for another server's priority.

Benchmark
---------
Same methodology as session-context-validation-20261115: two clients per
transport, Ping interval/window/offline tolerance 1000 ms; peer query once per
second. TCP and UDP each ran a 600-second healthy baseline followed by six cuts:
3, 10, 60 seconds for each client. Private process-specific TCP silence / UDP
datagram-drop relays affected only benchmark workers, not host networking.
Telemetry disabled. UDP reused saved registration state sequentially from the
previous normally stopped run. No concurrent reuse of an identity.

Both baselines: zero false local/peer Offline, Unknown or query errors.
All 12 cuts observed real Offline and recovered to stable Online. No failed or
censored trial and no worker restart. Stable means at least five continuous
seconds Online; latency below is the start of that interval. Each restored
trial retained roughly 25 seconds of observation. No claim about P2P streaming.

Client A: local 0.595 s, peer 1.308 s (previously 7.127 / 7.142 s).

The previously delayed cases now recover through fresh probes. Maxima remain

Peer Offline timing includes a one-second polling phase, so differences of
hundreds of milliseconds alone do not establish a performance regression.
